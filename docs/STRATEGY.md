## 1. メディアコンセプトとターゲット定義

### 1-1. メディアコンセプト（一文）

> **「足の機能を取り戻す」を軸に、熊本の農家が畑の泥・雨・砂利で毎日実地テストした一次データで、ベアフットシューズの選び方と移行を案内する日本語専門メディア。**

補足: 「農家のメディア」ではない。一般層向けの「足の健康×靴選び」メディアであり、農家性は全記事の信頼の根拠（署名＝コストリー・シグナリング）として機能させる（CLAUDE.md 戦略原則2）。

### 1-2. ターゲット定義（ペルソナ4種）

| # | ペルソナ | 状況・悩み | 入口クエリ（keyword-map対応） | 出口（LM/商品） |
|---|---|---|---|---|
| P1 | **健康志向層**（30〜50代男女。デスクワーク中心、健康情報に感度が高い） | 外反母趾・扁平足・浮き指などの足トラブル予備軍。「靴で矯正」ではなく「足を鍛える」発想に共感する | 「ベアフットシューズ 効果」「足指 鍛える」「外反母趾 ベアフットシューズ」「土踏まず 作り方」 | LM2（足指セルフチェック）→ 入門価格帯（SAGUARO・無印）→ 定番（メレル） |
| P2 | **立ち仕事層**（販売・調理・製造・医療など。1日8時間以上立つ） | 足裏の痛み・夕方のむくみ・疲労。「疲れない靴」を探し続けてクッション系で解決しなかった経験がある | 「立ち仕事 足の裏が痛い」「足底筋膜炎 靴」「疲れない靴 立ち仕事（ロングテール）」 | LM2 → シーン別比較（普段履き・ビジネス）→ 高耐久モデル |
| P3 | **ランナー**（フォアフット・ゼロドロップに関心のある市民ランナー） | 膝痛・故障予防。厚底に疑問を持ち始めた層。移行失敗（ふくらはぎ・アキレス腱）への不安が強い | 「ベアフットシューズ ランニング」「ゼロドロップ デメリット」「フォアフット走法」「ワラーチ」 | LM1（30日移行カレンダー）→ Xero・Altra・Merrell等の中〜高単価帯 |
| P4 | **ガーデニング・外仕事層**（家庭菜園・ガーデニング愛好家、兼業農家、屋外作業者） | 長靴は蒸れて疲れる、地面の感覚がない。「土に触れる暮らし」への志向 | 「ガーデニング 靴」「農作業 靴 疲れない」「地下足袋 効果」 | LM1/LM2 → 丸五・作業系 → **将来の自社製品のコアターゲット** |

- 集客ボリュームの主力はP1・P2（健康隣接クラスタが最大の池。keyword-map サマリー参照）。
- P4は検索ボリュームこそ小さい（仮説: 5K〜15K/月）が、**最終製品「外仕事・ガーデニング・アウトドアワークのためのベアフットシューズ」の一次顧客候補**であり、リスト内でのタグ管理を必須とする（→ 第7節）。

## 2. ポジショニング（競合分析から導いた勝ち筋）

### 2-1. ポジショニング・ステートメント

**「中立比較 × 足の専門性 × 実地テスト」の三位一体を同時に持つ、日本語圏唯一のプレイヤーになる。**

competitors.md の横断観察どおり、この3つを同時に持つ競合は不在: マイベストは中立だが素人（実測・実使用なし）、こば氏（義肢装具士note）は専門だが比較DBとフィールドデータがない、ブランド公式は詳しいが中立でない、外反母趾系通販は思想が真逆（アーチサポート推し）。

### 2-2. 勝ち筋5点（competitors.md §3 を核に）

1. **再現不可能な一次情報＝「畑テスト」**: 泥・雨・砂利・長時間立ち仕事という悪条件での耐久・グリップ・防水・疲労の定量ログは、東京の編集部にも店舗専門家にも売る側にも物理的に作れない。全記事の信頼の根拠にする（→ 第5節でブランド化）。
2. **LLMO完全実装の先行者利益**: FAQ/Product/Article構造化データ・数値基準つき定義文・実測比較表は業界全体でほぼ空白（llmo-audit §2）。note依存のこば氏は構造的に実装できない。AI検索の引用元ポジションを今から独占する。
3. **「中立比較×移行ガイド×実地データ」の三位一体**: 特に「外反母趾・足底筋膜炎 → 足を鍛える → ベアフットという選択肢」の橋渡しは、サポート思想の通販（welleg等）が構造的に書けない最大の空白。
4. **メールリスト＝出口設計の違い**: 競合の出口はアフィリ送客・自社EC・来院・月額課金。「読者の悩みを解決しながらリストを育て、最終的にファブレス自社製品を届ける」製品開発前提のメディアは不在。レビューで見つけた「市販品が満たせない要件」がそのまま製品仕様になる＝調査費ゼロのR&D。
5. **農作業・外仕事クラスタの無血開城**: 「農作業 靴」SERPは長靴一色で足の健康視点ゼロ。大手には参入する理由がない領域を、差別化・被リンク・AI引用・製品ターゲットの池として独占する。

### 2-3. 警戒対象と非競合方針

- 唯一の脅威（仮説）は、こば氏がnoteを出てSEO設計されたオウンドメディアを持つケース。ただし「毎日更新×臨床」の型はフィールドテストと排他的で正面衝突しない。**競合ではなく将来の監修・対談候補として関係構築する**（content-calendar 次アクション2と整合）。
- 編集方針の事前確定事項（keyword-map 運用メモ）: 「ミニマリストシューズ」は断捨離文脈と混線するため記事設計時に切り分ける。「インソール」はベアフット思想と矛盾しうるため、「一時的な補助としては否定しない／長期は足を鍛える方向へ」の両論併記スタンスを標準とする。

## 3. キーワード戦略サマリー

### 3-1. 狙うクラスタと攻略順（4ハブ構成）

keyword-map.md の★（約45個）と content-calendar の公開順に準拠。

| 順 | フェーズ（月） | クラスタ | 代表★キーワード | ねらい |
|---|---|---|---|---|
| 1 | 第1月: 低KD即効枠 | **入門・悩み系**（Know） | デメリット／慣らし方／歩き方／安い／ワークマン／SAGUARO | 難易度「低」★で早期のインデックス・流入・AI引用実績。LM1導線を最初に確立 |
| 2 | 第2月: クラスタ拡張 | **健康隣接**（外反母趾・足指・浮き指）＋**シーン比較**（普段履き・幅広・ビジネス） | ベアフットシューズ 外反母趾／足指 鍛える／普段履き／幅広 | 最大の池（健康隣接、仮説: 100K超/月）へロングテールから橋を架ける。LM2導線を確立 |
| 3 | 第3月: 柱記事投入 | **定義柱**「とは・効果」＋**比較柱**「おすすめ」 | ベアフットシューズ とは／効果／おすすめ | クラスタ15本の内部リンクで下から支えてからビッグKWを投入。防水・冬★は季節需要（晩秋想定）に合わせる |
| 4 | 第4月以降 | **指名レビュー拡張**＋Buy系 | ビボベアフット 評判／サイズ感系／取扱店 | 購入直前クエリで収益効率を上げる。取扱店まとめは更新性で堀になる |

### 3-2. 戦略の要点

- **最大の池は「ベアフット系」ではなく健康隣接系**（外反母趾・足底筋膜炎・足指トレ・立ち仕事）。ビッグワード（「外反母趾 治し方」等）は医療機関が独占するため直接狙わず、「◯◯ ベアフットシューズ」型のロングテール（競合ほぼ不在）から入り、「足の機能を取り戻す→ベアフットという選択肢」の橋渡し記事を集客8割の実体にする。
- **ベアフット系SERPは個人ブログ・noteが上位に入る過渡期**であり、新規ドメインでも専門性×一次情報で参入可能（competitors.md §2-3）。この窓が閉じる前に第1〜3月の20記事を投入する。
- **柱記事は最後に出す**（仮説: クラスタが内部リンクで支える構造ができてから柱を出す方がビッグKWの初期評価が付きやすい）。
- 農作業・外仕事系クエリは流入目的にしない（直接掛け合わせは仮説: 月間100未満）。差別化・被リンク・AI引用・製品ターゲット池として2割枠で書く。
- **注**: 本節のボリューム・難易度はすべてkeyword-map v1の概算値。Ahrefs導入後に★を再判定し、本節と content-calendar を連動更新する。

## 4. 収益化ロードマップ（アフィリエイト → リスト → 製品）

### 4-1. 三段階の全体像

```
Phase 1（0〜6ヶ月）アフィリエイト基盤
  Amazon 8%主軸 + 楽天4%併記。メディアの運転資金と検証データを稼ぐ
Phase 2（3〜12ヶ月）リスト構築 ※Phase 1と並走
  LM1/LM2でメール登録を積む。真の資産はここ（戦略原則3）
Phase 3（12ヶ月〜）自社製品
  リストの「市販品の欠落要件」を製品仕様化 → ファブレス開発 → クラファン
```

### 4-2. Phase 1: アフィリエイトの現実条件（affiliate-programs.md 反映）

| 条件 | 運用ルール |
|---|---|
| **Amazon 8%が主軸**（シューズカテゴリ） | 全レビュー・比較記事の第一リンク。ただし商品によりスポーツ&アウトドア扱い(4%)の可能性があり、登録後にASIN単位で要確認 |
| **紹介料上限1商品1,000円のリスク（要確認）** | 12,500円超の商品（メレル上位・Xero・Vibram・Altra・Vivobarefoot）は上限に当たる可能性。**高単価品は楽天リンク併記を必須の運用ルールとする**（楽天4%・上限緩め・料率アップキャンペーン時は差し替え） |
| **ワークマンはアフィリエイト経路ゼロ** | 建さんII等の記事は集客・信頼構築専用と割り切り、記事内で「次の一足」としてSAGUARO・メレル等（Amazon/楽天リンクあり）へ内部誘導して回収する |
| ブランド独自アフィリエイトは日本市場にほぼ無い | Xero本家10%（cookie60日）等は日本読者の国内購入に紐づかない点に注意。A8/もしも/バリュコマの独自案件はASP登録後に管理画面で再検索 |
| 価格帯別の役割分担 | 低価格帯（SAGUARO・無印・丸五）＝Amazon 8%で件数を稼ぐ／高価格帯（メレル〜Vivo）＝レビューの深さ×楽天併記で単価を取る／ワークマン・地下足袋＝集客・差別化用 |

- 初期投資: 実物レビュー用10足＝約102,000円（二段構え可: 先に約3万円→反応を見て追加。content-calendar §4）。

### 4-3. Phase 2: メールリスト構築（真の目的）

- **リードマグネット2本**（content-calendar §1-3）:
  - LM1「ベアフット移行30日カレンダーPDF」— 入門・比較・レビュー系読者向け。仮説: 購入直後の「移行に失敗したくない」不安に刺さるため登録率が最も高い導線
  - LM2「足指セルフチェック＆7日トレーニングシートPDF」— 健康系読者向け
- 全記事末尾＋記事中CTAでメール登録へ。読者タイプ別に2導線で振り分ける。
- 登録時にペルソナ推定タグ（流入記事クラスタ由来: 健康/立ち仕事/ラン/ガーデニング）を付与し、Phase 3の製品アンケート対象抽出に備える。

### 4-4. Phase 3: 自社製品（ファブレス開発 → クラファン）

- 最終製品の定義（戦略原則5）: 「農作業靴」ではなく**「外仕事・ガーデニング・アウトドアワークのためのベアフットシューズ」**。「熊本の農家が自分のために作った」は開発ストーリー内でのみ使う。
- レビュー記事の運用自体をR&Dにする: 各レビューで「市販品の欠落要件」（例: 防水×薄底×耐泥の両立不可、トゥボックス幅不足、ソール摩耗の早さ）を定型記録し、製品仕様の候補リストとして蓄積する（→ 第7節の手順）。
- 委託先候補: くつなび運営元の岡畑興産はシューズOEM受託事業を持つ（competitors.md 1-5。仮説: 競合ではなくファブレス開発の窓口候補）。

## 5. コンテンツ運用ルール

1. **8:2比率の厳守**（戦略原則1・2）: 集客層（入門・健康・比較・レビュー）8割／差別化層（畑実地テスト・地下足袋論・外仕事×足の健康）2割。差別化層は検索流入目的ではなく、一次情報の証拠・被リンク・SNSシェア・AI引用・製品ターゲット池として設計する。
2. **農家性は署名であってテーマではない**: 全記事の著者ボックス（C5）とテスト条件ブロック（R2）で「畑で実地テストしている人間」であることを示す。農家をテーマにするのは2割枠のみ。
3. **トーン**: 中立・誠実・定量的。誇大主張をしない（効果は「主張×根拠レベル表」で提示）。健康系は両論併記＋受診推奨ラインを必須とし、断定を避ける。デメリットを隠さず「デメリット→対処法→移行スケジュール」の三点セットで書く。
4. **LLMO要件**: 全記事に llmo-audit.md §3-0 の**共通8要件（C1〜C8）を適用**する — C1 冒頭定義文（80〜120字・数値1つ以上）／C2 H2直下アンサーファースト／C3 構造化データ（Article+BreadcrumbList必須、FAQPage/Product/ItemListを該当時）／C4 FAQ最低5問・健康系7問以上／C5 著者ボックス＋テストポリシーへのリンク／C6 一次情報の定量化（期間・距離・路面・天候・体重/負荷の5属性）／C7 更新日と実測日の明示／C8 研究引用の形式（出典名＋年＋数値＋リンク）。記事タイプ別に定義型(D)/比較型(H)/レビュー型(R)/健康系(M)テンプレートを併用する。
5. **「畑テスト」の定型計測をブランド化する**: テストポリシーページを1本立て（content-calendar #8）、「全商品を熊本の農地（泥濘・砂利農道・畦道・舗装路）で最低◯日・◯km歩いて評価」と宣言。定型計測項目＝**雨天グリップ／泥詰まり／浸水までの時間／ソール摩耗（期間つき）**＋実測スペック（重量・ソール厚・ドロップ・トゥボックス幅）。全レビューで統一フォーマットにすることでメディア横断の比較可能性＝独自データベースになる（llmo-audit §4）。
6. **数値の取り扱い**（CLAUDE.md 作業ルール）: 数字には取得日と出典を併記。推測には「仮説:」を付ける。公称値と実測値は必ず併記する（差分自体が独自データ）。
7. **監修**: 健康系記事（M系）は理学療法士・義肢装具士・整形外科医いずれかの監修確保を目指す。間に合わない場合は「専門家見解の引用＋受診推奨ライン明記」で先行公開し、監修取得後にリライト（content-calendar #13の方針を標準化）。

## 6. KPI（6ヶ月後・12ヶ月後）

> **注記**: 本節の目標値はすべて「仮説」であり、根拠となる検索ボリューム・難易度は keyword-map.md v1 の**概算値**（Googleサジェスト＋SERP観察からの推定）に依拠する。**Ahrefs接続後に実数値で本節を更新する。** 収益係数（CTR・CVR・客単価）も業界一般値からの仮置きで、実績3ヶ月分が溜まった時点で実測値に置換する。

### 6-1. KPIツリー（3指標）

| 指標 | 6ヶ月後（2027-02） | 12ヶ月後（2027-08） |
|---|---|---|
| 月間セッション数 | 仮説: **8,000** | 仮説: **35,000** |
| メールリスト累計登録数 | 仮説: **250人** | 仮説: **1,200人** |
| 月間アフィリエイト収益 | 仮説: **15,000円** | 仮説: **80,000円** |

### 6-2. 根拠

- **セッション（6ヶ月・8,000）**: 第3月末までに20記事、第6月までに累計35〜40記事を想定。狙う★キーワードは難易度「低〜中」中心で、立ち上げ期の獲得可能池は「ベアフット入門・比較系 合計20K〜50K/月（概算）」のロングテール部分＋健康隣接ロングテール。新規ドメインの検索評価立ち上がりが3〜6ヶ月かかる一般則を踏まえ、1記事平均200セッション/月×40記事＝8,000と置く。仮説: ★キーワードの半数で上位5位以内に入れれば達成圏。
- **セッション（12ヶ月・35,000）**: 累計70〜80記事＋柱記事（とは/効果/おすすめ）のミドルワード上位化＋AI検索経由の指名流入を想定。健康隣接クラスタ（概算100K超/月）への橋渡し記事が機能し始める前提。1記事平均450セッション/月×78記事相当。競合分析どおり「過渡期の窓」で先行できた場合の数字であり、窓が閉じれば下振れする。
- **リスト（250人 → 1,200人）**: 登録率をセッション比0.5%と仮置き（LM×記事内CTAの2導線。コンテンツ適合が高いニッチメディアの一般的水準0.3〜1.0%の中央下寄り）。6ヶ月: 累計セッション約2.5万×0.5%＋α ≒ 250人。12ヶ月: 累計セッション約20万×0.5%＋登録率改善分 ≒ 1,200人。
- **収益（15,000円 → 80,000円）**: 収益記事（レビュー・比較）へのセッション比40%、アフィリリンクCTR 8%、CV率 3%、平均報酬単価600円（Amazon 8%×低中価格帯中心、上限1,000円リスク込み）と仮置き。6ヶ月: 8,000×0.4×0.08×0.03×600円 ≒ 4,600円/月 … に季節要因（防水・冬記事）と楽天併記分を加え15,000円を上限目標として設定。12ヶ月: 35,000セッションで同係数＋単価改善（高単価レビューの比重増）で80,000円。**収益は3指標の中で最も不確実性が高い**（Amazon上限1,000円規定の確認結果で大きく変わる）。
- **先行指標（月次で監視）**: 新規記事のインデックス速度／★キーワードの順位分布／AI検索（Perplexity等）での引用確認数／LM別登録率。KPI未達時はまずこの4つで原因を切り分ける。

### 6-3. KPI未達時の見直しルール

- 3ヶ月時点でセッションが計画の50%未満: ★キーワードの再選定（Ahrefs実数値ベース）と第4月以降の記事タイプ配分を見直す。
- 登録率が0.25%未満: LMのオファー（タイトル・訴求）とCTA位置をABテスト。
- 収益が計画の50%未満でもリストが計画以上: 戦略は継続（リストが本命資産のため。戦略原則3）。

## 7. 製品開発への接続条件

Phase 3（自社製品）へ進む判断は感覚でなく、以下の条件と手順で行う。

### 7-1. ゲート条件（すべて「仮説:」— 実績を見て閾値を調整）

| ゲート | 条件 | 実施すること |
|---|---|---|
| G1: 製品仮説アンケート | 仮説: **メールリスト500人到達**（うちP4=外仕事・ガーデニングタグ100人以上） | リスト向けに製品仮説アンケートを実施（欲しい機能・価格受容帯・現状の靴の不満）。回答100件以上を有効ラインとする |
| G2: 仕様確定 | G1で「防水・耐久・トゥボックス幅」等の上位不満に**回答者の30%以上が価格2万円前後でも欲しい**と回答 | 「市販品の欠落要件リスト」（7-2）から製品仕様v1を確定。OEM先（岡畑興産等）へ見積・サンプル打診 |
| G3: クラファン開始 | 仮説: **リスト1,200人以上**（12ヶ月KPI達成）＋サンプル実地テスト（自分の畑で1シーズン）完了＋原価・目標調達額の成立確認 | Makuake等でクラファン開始。初日案内をリスト全員に配信（このために作ったリスト） |

### 7-2. 「市販品の欠落要件」リスト → 製品仕様への転換手順

1. **蓄積**: 全レビュー記事の執筆時に、定型計測（雨天グリップ・泥詰まり・浸水時間・ソール摩耗）と着用ログから「この商品が満たせなかった要件」を記録する。記録先はシューズDB（REQUIREMENTS.md のスキーマに `missingRequirements` フィールドを常設）。
2. **集計**: 四半期ごとに欠落要件を頻度順に集計し、「どのペルソナが・どのシーンで・何に困るか」の形式に正規化する（例: P4×雨天の畑×「防水を謳う薄底靴は浸水まで平均◯分」）。
3. **照合**: G1アンケートの不満回答と欠落要件リストを突き合わせ、**実地テストとリストの声の両方で裏付けられた要件だけ**を製品仕様v1に採用する（片方だけの要件は「v2候補」に落とす）。
4. **ストーリー化**: 採用した各仕様に対応するレビュー記事・テストログを紐付け、クラファンページの開発ストーリー（「熊本の農家が自分のために作った」はここでのみ使用）の素材にする。

### 7-3. 撤退・保留ライン

- 仮説: 12ヶ月時点でリスト500人未満、またはG1アンケートの価格受容が成立しない場合、製品開発は保留しメディア（アフィリ＋リスト）の成長に集中する。メディア単体でも事業として成立する設計を崩さない。
